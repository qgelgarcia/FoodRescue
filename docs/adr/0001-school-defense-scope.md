# School defense with a shared core workflow

FoodRescue's current delivery target is a school defense with a real shared workflow backed by Supabase. Two separate accounts must be able to post food, submit a claim, approve it as the donor, and confirm pickup as the donor. Features deferred from this delivery must be explicitly documented rather than presented as working capabilities.

We chose this scope over a local simulated demonstration or a campus pilot to provide credible evidence of the core workflow without requiring all operational features before the defense. The completed interview additionally requires Android APK delivery, live QR/manual pickup, maps/uploads, foreground journey sharing, and audited admin moderation. SMS integration/setup, background tracking, bans, broadcasts, and advanced analytics are deferred. See the confirmed Design_Agreement_FoodRescue.md for the full reconciled scope.
